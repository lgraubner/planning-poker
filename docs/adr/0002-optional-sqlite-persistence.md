# Optional SQLite persistence

Setting `DATABASE_PATH` keeps rooms in a SQLite file so they survive restarts, relaxing the restart-durability trade-off of ADR 0001; without it, rooms stay in memory only. The in-memory map remains the live state and every room change is written through synchronously under the store lock, using the pure-Go `modernc.org/sqlite` driver so the binary stays static. Only room-level state is stored, because participants and estimates already vanish seconds after disconnecting, and persisted rooms expire after 30 idle days instead of one hour. The room limit rises from 1,000 to 100,000 so a flood cannot block room creation for a month; it stays bounded because every room is also held in memory and each room makes codes easier to guess. Writes use `synchronous=NORMAL`, so a power loss may drop the last few changes but never corrupts the file. Rate limits stay in memory: their buckets refill within a minute, so a restart only grants one fresh burst. Exactly one replica is still required.
